## 一、 项目背景与赛事目标

### 1. 赛事背景
- **活动名称**：2026 麦当劳程序员创意开发大赛（联合腾讯 WorkBuddy）。
- **评审机制**：以参赛项目在 GitHub 平台获得的**公开 Star 数量**严格排名；前 100 名入围获奖池，前 3 名设大奖。
- **专项奖励**：真实使用腾讯 WorkBuddy 开发并提交 `workbuddy.md` 的前 100 名项目，每人额外获得 3000 积分。
- **时间约束**：2026-10-09 至 2026-10-25，Star 封榜 2026-10-26 00:00。**开发窗口仅剩约 12 天，所有规划按此倒排。**

### 2. 用户痛点与业务切入点
1. **控卡人群的快餐焦虑**：当代打工人和健身群体习惯吃麦当劳，但难以精准量化卡路里、蛋白质，担心热量超标。
2. **传统健身软件的繁琐性**：传统饮食记录软件需要用户手工逐一搜寻单品，操作链路冗长，缺乏正向情绪激励。
3. **优惠体系过于复杂**：麦当劳卡券体系（麦麦省券、会员券、随心配 1+1、积分商城等）繁多，普通用户极难在"控制热量"的同时"兼顾极致性价比"。

### 3. 制胜逻辑（Star 导向）
- 评委（路人）点 Star 只看 30 秒：**README 中的演示 GIF 是本项目的核心资产**，与功能代码同级优先，而非文档收尾工作。
- 功能越贴近"程序员减肥控卡 + 打工人省钱凑单"的高共鸣场景，越容易在技术圈、朋友圈快速裂变。

## 三、 核心功能模块详细设计

### 模块 1：用户身材档案与 TDEE 科学热量模型
- **功能描述**：录入用户个人基础身体数据，科学计算每日能量代谢基线。
- **算法模型**：采用国际权威 **Mifflin-St Jeor 公式**：
  - 男性：BMR = (10 × 体重kg) + (6.25 × 身高cm) − (5 × 年龄) + 5
  - 女性：BMR = (10 × 体重kg) + (6.25 × 身高cm) − (5 × 年龄) − 161
  - TDEE = BMR × 运动活动系数（久坐 1.2 / 轻度 1.375 / 中度 1.55 / 高强 1.725）
- **交付指标**：自动推导单餐推荐热量上限、蛋白质目标摄入区间（如减脂期按 1.6~2.0 g/kg 体重换算）。
- **隐私红线**：所有身体数据**仅存于用户本地**（浏览器本地存储 / 本地数据文件），不上传任何服务器，不参与分享导出（海报默认不含体重等原始身体数据）。

### 模块 2：麦当劳官方 MCP 数据联动中心
深度集成麦当劳中国官方远程 MCP Server（`https://mcp.mcd.cn`），调度 6 大核心 Tools：

| # | Tool | 用途 |
|---|---|---|
| 1 | `list-nutrition-foods` | 获取单品官方真实热量、蛋白质、脂肪、碳水、钠等指标，做营养打标 |
| 2 | `auto-bind-coupons` | 冷启动时一键同步领取麦麦省最新优惠券 |
| 3 | `query-my-coupons` | 读取用户当前卡包所有可用卡券明细 |
| 4 | `query-meals` | 获取所在门店实时可售卖的单品与分类菜单 |
| 5 | `calculate-price` | 校验最终搭配方案并获取官方精准折后实付价 |
| 6 | `campaign-calendar` | 查询今日特惠、会员日活动日历 |

**范围说明（v1.1 收敛）**：以业务需要为准则，**不追求用满官方全部开放接口**。积分商城（`query-my-account` / `mall-points-products`）、下单（`create-order`）等本期一律不接，MCP_INTEGRATION.md 中工具清单与本表严格一致。

### 模块 3：运动代偿换算器 (Exercise Equivalent) · 正向激励版
- **功能描述**：将本餐摄入热量或差额，转化为生动、可量化的运动参考指标。
- **换算基准模型（均为估算值，仅供参考，不构成专业建议）**：
  - 慢跑（8 km/h）：消耗(kcal) ≈ 体重(kg) × 距离(km) × 1.036
  - 俯卧撑：约 0.5~0.6 kcal / 个
  - 跳绳（中速）：约 10~12 kcal / 分钟
  - 快走（5 km/h）：约 130 步 ≈ 5 kcal
- **文案框架（v1.1 关键调整——弃用负罪感口径，全程正向激励）**：
  - 达标时：
    > "本餐摄入 620 kcal，处于健康减脂区间！相当于慢跑 5.4 公里即可消耗，今天也是自律的一天 🎉"
  - 超标时（行动导向，非惩罚导向）：
    > "本餐超出预算 180 kcal —— 今晚快走约 25 分钟（≈4700 步）即可回归平衡，明天继续加油！"
  - **禁止出现**："反省"、"放纵"、"惩罚"类字眼；超标印章同步更名（见模块 4）。
- **设计依据**：健身产品的留存逻辑是"让用户愿意回来"，负罪感文案会显著提高弃用率；超标后的正确姿势是给一个"低门槛的补救动作"，而非情绪审判。

### 模块 4：定制食物贴纸 · 每日打卡日历看板 (核心视觉与留存高光)
- **日历矩阵视图**：按月份渲染网格日历，直观展现当月每日打卡状态（达标-绿色 / 维持-蓝色 / 超标-橙色）。
- **定制食物贴纸合成机制**：
  - 贴纸由当天实际选中的麦当劳餐品动态组合生成（如：板烧堡图标 + 玉米杯图标 + 纯黑咖啡图标）。
  - **素材实现方式（v1.1 明确）**：全部使用**项目内自绘 SVG 简笔图标**（线条轮廓风格），**严禁使用麦当劳官方 Logo、餐品实拍图、官方物料**——此为参赛声明知识产权红线的硬性要求。
  - 根据控卡达标情况，加盖状态印章：
    - 达标 → "麦门减脂自律先锋印"（正向，保留）
    - 超标 → "麦门弹性平衡章"（v1.1 由"放纵反省章"更名，中性鼓励口径）
- **社交分享卡片**：一键导出今日打卡长图/海报，**默认脱敏**（不含体重、TDEE 等身体原始数据，仅展示餐品贴纸、热量与运动换算结果），强化社交裂变与传播属性。

### 模块 5：Agent 私教决策引擎 (ReAct 思维链) · 【后置加分项】
- **定位**：路线图最后一站（Phase 5）。轨道 A 完整交付且材料齐备后，用富余时间开发；若时间不足，以"规则引擎版教练建议按钮"作为降级交付（纯算法，零 API Key 可运行）。
- **降级版（规则引擎）逻辑**：
  1. 读取用户当日热量差额与蛋白质缺口；
  2. 从 `list-nutrition-foods` 候选集中筛选高蛋白低卡单品；
  3. 结合 `query-my-coupons` 卡券与随心配 1+1 规则，穷举最优组合；
  4. `calculate-price` 校验折后价，一键回填轨道 A 勾选框。
- **完整版（LLM ReAct 思维链）System Prompt 核心约束**：
  - 强约束 1：总热量偏差不超过目标值的 ±50 kcal；
  - 强约束 2：高蛋白优先，剔除油炸高脂单品（如推荐板烧去酱、双吉、去皮大脆鸡）；
  - 强约束 3：必须使用优惠券或 1+1 随心配压低实付金额。
- **思维链推导闭环 (ReAct)**：
  1. **Thought 1**：分析用户热量差额、蛋白质指标与预算；
  2. **Action 1**：调取 `list-nutrition-foods` 筛选高蛋白低卡单品候选集；
  3. **Action 2**：调取 `query-my-coupons` 匹配候选集优惠券；
  4. **Thought 2**：综合求解出最优组合（如随心配 + 领券单品）；
  5. **Action 3**：调取 `calculate-price` 校验折后总价；
  6. **Final Output**：输出教练建议，并将餐品自动回填至轨道 A 的前端勾选框中。

## 四、 用户故事（核心场景）

1. 作为**减脂期程序员**，我希望在麦当劳点餐前快速看到所选组合的总热量和蛋白量，以便不用心算就能守住今日控卡目标。
2. 作为**精打细算的打工人**，我希望系统自动对比卡券/随心配/单点的实付价，以便同一顿饭花最少的钱。
3. 作为**打卡爱好者**，我希望每天生成专属食物贴纸并一键导出海报，以便在朋友圈/技术群晒图（顺带帮我拉票）。
4. 作为**克隆仓库的评委/路人**，我希望不配置任何 LLM Key、三行命令就能跑起来，以便 30 秒内看到效果并决定是否点 Star。

## 五、 Non-goals（本期明确不做）

1. **不做真实下单**：不调用 `create-order`，不产生任何真实订单与支付行为。
2. **不做医疗/营养专业建议**：所有输出均为估算参考，页面标注免责口径（与 CONTEST_DECLARATION 一致）。
3. **不做账号体系与云同步**：无注册、无登录、无服务端存储；MCP Token 由用户本地配置。
4. **不接积分商城类接口**：`query-my-account`、`mall-points-products` 本期不接（见模块 2 范围说明）。
5. **不做移动端原生 App**：仅提供 Streamlit 响应式 Web 界面。
6. **Agent 私教不进 P0 承诺**：轨道 B 为加分项，不因它拖延轨道 A 与参赛材料。

## 六、 技术架构与选型方案

```
[前端表现层]  Streamlit (麦当劳红黄品牌视觉，支持响应式布局、数据看板与日历组件)
     │
[智能调度层]  Python 规则引擎（P0~P4）/ 轻量 ReAct Agent 内核（P5 加分）
     │
[业务算法层]  TDEE 科学模型 / 运动消耗代偿模型 / 优惠券凑单比价算法 / 自绘SVG贴纸组合引擎
     │
[协议通信层]  Streamable HTTP 客户端封装 (标准 JSON-RPC 通信，支持流量控制)
     │
[底层数据源]  麦当劳中国远程 MCP Server (https://mcp.mcd.cn)
```

- **高可用与零门槛设计**：
  - 提供"本地确定性算法模式"与"大模型增强模式（仅 P5 需要）"；
  - 即使使用者不配置任何 LLM API Key，也能完整运行本地算法、拉取 MCP 真实数据并使用贴纸日历，保证克隆代码的用户零门槛体验与给 Star。
  - **运行方式明确写入 README**：`pip install -r requirements.txt` → 填入 MCP Token → `streamlit run app.py`，三步即跑。

## 十、 开发推进路线图 (Roadmap) · 按 12 天倒排

> 距 Star 封榜（10-26 00:00）仅剩约 12 天，以下按"P0 保入围 → P1 提观感 → 加分项"倒排。

1. **Phase 1（约 10-13 ~ 10-16）基础数据与算法**：
   完成 `tdee_calculator.py`（代谢公式与运动换算，正向文案口径）、`mcp_client.py`（麦当劳 MCP 请求封装）、优惠券凑单比价核心算法。
2. **Phase 2（约 10-17 ~ 10-19）界面与交互 + 首版 README/GIF**：

3. **Phase 3（约 10-20 ~ 10-22）贴纸日历与运动换算**：
   打卡记录本地存储、自绘 SVG 贴纸引擎、日历看板、脱敏海报导出、正向运动代偿换算落地。

   终版 README/GIF、`MCP_INTEGRATION.md`、`workbuddy.md` 导出、红线自查（Token/隐私/素材）、提交 Issue 报名，随即启动拉票。
5. **Phase 5（10-24 之后，加分项）Agent 智能私教（轨道 B）**：
   上述全部完成且时间富余时，先上"规则引擎版教练建议按钮"（零 Key 可跑），再视情况接入 LLM ReAct 思维链；时间不足则本期放弃，不影响参赛资格。
